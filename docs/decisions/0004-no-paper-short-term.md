# ADR-0004：短期不做论文，先做工具

- 状态：Accepted
- 日期：2026-11-14
- 决策者：项目所有者

## 背景

- 项目有论文潜力（DSU / 不可合作二进制插件 / Minecraft 作为极端案例），但论文需要严谨的分类学、测量、评估、合作者。
- 所有者明确表示：**短期目标不是论文，考上研究生之后再考虑。**
- 当前更缺的是：可用工具、真实语料、社区反馈、T4 软重启的可行性。

## 决策

- **未来 6 个月不安排论文产出**：不写 abstract、不做投稿计划、不为审稿人设计评估。
- 调研/路线文档里的论文部分**保留为长期备选**，但不得驱动短期优先级。
- 仍然保留“可复现的实验记录”（命令、版本、结果），因为工具质量本身需要它，而不是为了论文。
- 如果后续要启动论文，另开 ADR，重新评估 novelty 与合作者。

## 后果

正面：

- 优先级清晰：工具 > 论文。
- 不会为了“可发表”而做不服务于用户的抽象。
- 节省时间给分析器校准和 T4 PoC。

负面：

- 可能错过“第一个系统测量”的窗口（Hotwire 等先行者也在积累数据）。
- 未来重启论文时需要补实验/标注。

缓解：

- `status.md` 持续记录表尺和证据，未来可直接复用。
- 语料和标注格式从 v0.1 就保持可导出（JSON），不锁死在工具里。

## 备选（未采用）

- **论文优先**：需要合作者、评估设计、投稿周期；与“先做社区工具”冲突。
- **完全放弃论文**：不必要；长期仍可作为差异化。
