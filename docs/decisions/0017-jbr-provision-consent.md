# ADR-0017：JBR 自动准备必须先显式同意，并展示官方链接与哈希

- 状态：**Accepted**（所有者 2026-11-22 发布前要求）
- 日期：2026-11-22
- 决策者：项目所有者

## 背景

“准备热加载环境”会联网下载 95–200 MB 的 JBR、解压到游戏目录，并重启游戏进程。
这套行为（自下载、写文件、自重启、改 JVM 参数）在 CurseForge / 杀软 / 玩家眼里都高度可疑；
项目已被 CurseForge 转人工审核。不能要求玩家或审核方凭信任接受这些动作。

同时，下载并不保证成功：需要网络/代理可达；只有 5 个平台资产（Windows x64/arm64、
macOS arm64、Linux x64/arm64），Intel macOS 没有 JBR 21 资产；GitHub Release 页面本身
**不托管二进制资产**，其说明里的下载链接仍指向 JetBrains 的 cache-redirector。

## 决策

1. **任何下载、解压、重启之前必须有显式同意页**。页面展示：
   - 固定的 JetBrains GitHub Release 页面（版本核验）；
   - 实际下载 URL（cache-redirector，固定文件名）；
   - 固定 SHA-512；
   - 安装目录与“保存并重启一次”的动作说明；
   - 复制发布页 / 复制下载地址 / 打开发布页 / 允许并继续 / 取消。
2. **只在“允许并继续”后**调用 `JbrProvisioner.install` 和 `Relauncher`；取消返回准备页，
   不产生网络/文件/进程副作用。手动安装是等价路径。
3. **没有固定资产的平台（如 Intel macOS）禁用允许按钮**，只提供手动安装/官方发布页；
   不猜测 URL，不执行未知文件。
4. **信任锚是固定的 SHA-512**；GitHub Release 页只用于人工核验版本与链接，
   不是第二个二进制镜像。发布页的 checksum 链接与固定值一致。
5. 不后台下载、不静默解压、不自动重启；玩家点一次“允许”才继续。

## 后果

- 首次准备多一次确认；对普通玩家仍然是一键（确认 → 下载 → 自动重启）。
- CurseForge/杀软可审计：URL、哈希、目标目录、动作全部在界面上可见、可复制。
- 下载失败（网络/平台/权限/磁盘）仍会保持游戏运行并给出错误；手动安装始终可用。

## 备选（未采用）

- 静默自动下载/重启：审核与信任风险不可接受。
- 只提供文档、不提供自动准备：违背 ADR-0015 的玩家侧零手工目标。
- 增加非官方镜像：不可验证，拒绝。
