# ADR-0003：先做只读分析器，再做游戏内解释，最后做 T4 软重启

- 状态：Accepted
- 日期：2026-11-14
- 决策者：项目所有者 + agent

## 背景

热替换的核心操作（改字节码、重建注册表、换代际）都可能：

- 让游戏半死、崩溃；
- 损坏存档；
- 破坏其他模组；
- 毁掉社区口碑（一次事故就够）。

而我们现在**没有**：

- 真实的切换成功率数据；
- 人工标注的 tier ground truth；
- 对 NeoForge `ModuleLayer` 的重建经验；
- 对客户端 GL/窗口所有权的研究。

直接做“热插拔”等于在没有地图的情况下跳崖。

## 决策

按以下顺序推进：

1. **只读分析器**（已完成 v0）：扫描 jar、输出 tier + reasons + confidence，不启动游戏、不写文件。
2. **游戏内解释**：`/modreload why <mod>`，复用同一套规则，让玩家/整合包作者在游戏里看到“为什么必须重启”。
3. **T4 软重启 R&D**：NeoForge 1.21.1，dogfood Ex Nihilo；先做 PoC，不承诺可用。
4. **T2/T3 安全切换**：在 T4 之后，或作为开发期工具并行。

## 后果

正面：

- 社区在几周内就有可用东西（解释器），不用等几个月。
- 分析器产出语料/标注，喂养后续切换器。
- 低风险建立信任；出错也不会坏存档。
- 为 T4 划清边界：哪些模组值得做软重启。

负面：

- 短期“看起来不酷”——只是分析，不是热插拔。
- 可能被误解为“又一个模组列表工具”。
- T4 的硬问题被推迟，真正的技术风险还在后面。

缓解：

- 在 UI/文档里明确“这是第一步，不是终点”。
- 用 Ex Nihilo 的 83 秒启动作为 T4 的目标指标，持续对外沟通。
- T4 PoC 尽早开始（并行），不要等分析器完美。

## 备选（未采用）

- **直接做 Fabric T3 热插拔**：Hotwire 已占位，差异化小，且无法 dogfood 作者自己的 NeoForge mod。
- **直接做 T4 软重启**：风险最高，几个月没有可发布物；失败则一无所有。
- **做模组管理器/Modrinth 客户端**：偏离核心问题，竞争激烈。
