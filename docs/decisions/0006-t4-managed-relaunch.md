# ADR-0006：T4 走 managed relaunch，不注入注册表

- 状态：Accepted
- 日期：2026-11-15
- 决策者：项目所有者（路线由 agent 提议，所有者采纳）

## 背景

T4 = 注册表内容（方块 / 物品 / 维度 / 数据包注册表）。调查后发现一个容易误判的点：

**`MappedRegistry.unfreeze()` 是 public 的**（NeoForge `BaseMappedRegistry` 里 protected，`MappedRegistry` 公开覆写），
所以"往冻结的注册表里写"技术上做得到。但 `unfreeze` 只解除写保护，**不重建任何依赖它的东西**：

| 依赖注册表的东西 | 构建时机 | 热加后 |
|---|---|---|
| `BlockState` / `Item` 映射、`Block.BLOCK_STATE_REGISTRY` | 构造时 | 新条目可能拿不到 id |
| 创造模式物品栏（`CreativeModeTabs`） | 启动期 | 新物品不出现 |
| `BlockEntityType` 与方块的绑定校验 | 启动期 | 放下就崩 |
| 标签 / 配方 / 战利品表（数据包） | 数据包加载 | 新方块没有挖掘等级/合成 |
| 模型 / blockstates / 语言（资源包） | 资源加载 | 紫黑方块 |
| 世界生成数据、已存区块 palette | 世界加载 | 存档不一致，且删不干净 |

另外，单人 integrated server 与客户端共享 JVM 里的静态注册表，但 per-world 的 `RegistryAccess`
（数据包注册表）随服务器生命周期存在，两边不会自动同步。

roadmap 原本就写明 T4 的路线是**进程内游戏层软重启（新 ClassLoader 世代）**，
代价是 MC 的类要重新加载一遍、GL/窗口/native/单例都要重建——这是数周级的工程，不是几天。

## 决策

1. **明确拒绝"注入式热加"**：不采用 `unfreeze` + 手工 `RegisterEvent` 重放。
   它会产生"看起来加载成功、实际半坏"的状态——比"明确告诉用户需要重启"伤害大得多，
   也违反硬规则 3（T4/T5 必须说需要重启）和项目对"可预测/可回滚"的承诺。
2. **第一步做 managed relaunch**：检测到 T4 变更后，保存世界、退出客户端、重新启动并回到原存档。
   语义诚实（"需要重启，我帮你重启并回到这里"），立刻对 Ex Nihilo 这类 dogfood 有用，
   同时是未来软重启失败时的兜底。
3. **第二步在 dedicated server 上做"一代重建" PoC**：没有 GL/窗口/输入，变量少得多，
   用以先验证 classloader 世代、注册表重建、模组列表重建这三件事。
4. **第三步**才评估客户端进程内软重启；只有前两步成立才投入。
5. 期间所有面向用户的文案保持"T4/T5 需要重启"，不得写成"支持热加"。

## 后果

正面：

- 现在就能交付"不用手动重启"的体验，而不是等一个数年工程。
- 风险可控：relaunch 不触碰运行中的注册表，存档一致性由正常存盘流程保证。
- 为软重启积累真实数据（重启耗时、失败率、存档状态）。

负面：

- T4 的准确语义仍是"重启"，不是"不重启"——产品叙事上要克制。
- managed relaunch 需要控制进程重启；第三方启动器 / 官方启动器下能力受限（待验证）。
- dedicated server 的一代重建 PoC 仍然很重，可能推翻"客户端软重启可行"的假设。

## 备选（未采用）

- **注入注册表（unfreeze + RegisterEvent 重放）**：被否，理由见上。
- **只给文档提示、不自动重启**：不解决痛点，用户仍要自己找启动器重启。
- **直接冲客户端软重启**：缺中间验证点，失败成本过高；先 server-only 更稳。

## 后续修订提示（2026-11-15，不改变本决策）

同日完成的 payload 主动适配（E1–E3：解冻 `NetworkRegistry.setup`、重放事件、修补连接的
`PayloadSetup`）证明了一件事：**"框架禁止的时机"并不等于"能力不可达"**，只要代价和副作用可控，
"主动适配"可以突破一部分启动期限制。

这**不改变**本 ADR 的决策——注册表的依赖面（`BlockState`/创造栏/数据包/资源包/存档 palette）
比网络通道大得多，风险量级不同。但它意味着 T4 开题时应当**先评估"注册表适配"是否成立**
（与 payload 同样的做法：解冻 + 重放 `RegisterEvent` + 重建依赖缓存），再决定是否仍走 relaunch。
该评估需要单独开 ADR（ADR-0008），并明确"已有存档不可用"这一硬约束。
