# Mod Reloader 0.1.0 — Release Notes（草案）

> **状态：DRAFT，待所有者真实复测后定稿。**
> 数据源：[docs/whitelist/mods.tsv](../whitelist/mods.tsv)（`python3 tools/whitelist.py check` 为唯一校验入口）。
> 本文只承诺 `state=verified` 的行；`candidate` / `fixing` 明确标注为“待复测”，不作为发布承诺。

## 1. 这是什么

Mod Reloader 是一个**运行时（runtime），不是 mod**：它热加载你已信任的第三方 NeoForge 模组，
不替代模组本身的功能。目标版本：**Minecraft 1.21.1 / NeoForge 21.1.265 / Java 21**。

支持的形状：
- **嫔级**：无 mixin、无注册表内容；
- **妃级**：mixin；改已加载类布局时需要 JBR 增强重定义；
- **贵妃级（实验性）**：方块/物品等注册表内容 + 资源包/创造栏 + datapack（**add-only**）；
- **皇后级**：删除、更新、已存在世界的世界生成等，**只提示重启**，不支持热加。

## 2. 安装与快速开始

1. 安装 **Java 21** 与 **NeoForge 21.1.265** 的 1.21.1 实例。
2. 把 `modreloader-0.1.0.jar` 放进 `mods/`。
3. 首次启动后，若左上角显示 JBR **未就绪（黄/红）**：点一次
   **「为热加载增强环境做准备」**（必要时自动下载/复用 JBR 并重启一次）。之后本会话不再需要参数或第二次准备。
4. 把要热加的 jar 放进 `mods/` 或 `modreloader/inbox`；在热加载菜单里点 **Load**
   （世界内可用 `/modreloader add <jar>`，专用服控制台可短名 + TAB）。
5. **可选扩展 `MixinRuntime`（modId `mr` ≥ 1.0.2）**：放进 `mods/` 后才启用妃级/Mixin 热加；
   它不是启动前置——缺少时运行时照常启动，菜单右上角会提示，预检会拦下妃级/Mixin 模组。

> 不要用运行中的进程替换已加载的 jar；更新/换版需要重启。

## 3. 能力分层（按机制）

| 机制 | 需要 JBR？ | 需要 MixinRuntime？ | 状态 |
|---|---|---|---|
| 嫔级：无 mixin、无注册表 | 否 | 否 | 已验证 |
| 妃级：mixin（方法体 / 目标未加载） | 否* | 是 | 已验证（A1.2） |
| 妃级：已加载类的**布局变更** | 是（enhanced） | 是 | 已验证（JBR J1） |
| 贵妃级：注册表内容 + datapack（add-only） | 视模组自身内容 | 视模组 | 已验证（fixture / dogfood） |
| 皇后级：删除 / 更新 / 已存在世界世界生成 / 类级 AT 去 final | 只能重启 | — | 不支持 |

\* 方法体级 mixin 在 stock JVM 可重定义；布局变更才需要 JBR。增强 JBR 下 late AT **自动启用**
（`-Dmodreloader.lateAt=false` 可显式关闭），玩家不需要第二个开关。

## 5. 已知限制

### 5.1 热加机制

- **一次性启动事件不重放**：模组在 `FMLClientSetupEvent` 之外的启动期注册/快照可能缺失；客户端重放是手写清单
  （`ReplayCatalog` + 注册审计兜底），未覆盖的事件只 warn（问题 21/26）。
- **构造器副作用不可撤销**：静态状态、线程、全局注册、第三方事件总线；失败后运行时置脏（`RunState`），
  后续 add 被拒，需要重启（问题 7/35）。
- **给已存在实例新增 mixin 字段**：旧实例保持 JVM 默认值；轻则值错（Jade 字体变暗），重则崩溃（Sodium J2，问题 45/56/61）。
- **删除 / 更新不支持**：已加载类无法卸载；运行中替换 jar 不支持。
- **类级 AT 去 final**：运行期不可用，只能启动期应用（JourneyMap/Iris）。
- **coremod**：只覆盖 class 级 `ICoreMod`；method/field 级不覆盖。
- **JiJ**：嵌套库进 module path；嵌套 mod 会建 container；GAMELIBRARY 嵌套 AT 与 `data/` 不单独注入。
- **资源重载与 chunk 重镶**：重载链已串行化；chunk 重镶由原版调度（问题 29，边界）。
- **MixinRuntime 是可选扩展**：不打包、不代下载；缺少时妃级/Mixin 不可用，运行时本身照常启动。

### 5.2 存档与数据

- **注册表内容提交不可回滚**：id 会写入存档；之后移除 jar 可能坏档。
- **datapack 只 add、不删/改**：注入后存档绑定 `mod/<modId>`；已存在世界的世界生成注册表仍需重启。
- **没有自动世界备份**：贵妃级内容热加前请自行备份；失败/崩溃可能触发 emergency save。

### 5.3 多人

- 服务端热加后**先通知在线客户端，再提交注册表 / 重载数据**；未装同一 jar 的客户端会被踢，
  且装回之前**连不回来**（ADR-0011）。
- 两端必须热加**同一批 jar**；条目集合不一致时客户端拒绝应用快照，不部分应用、不踢人。
- 服务端一次性事件（`ServerStarting/Started`）重放已实现但**验证不足**（问题 52）。

### 5.4 平台与验证范围

- 已实测：**macOS arm64** dev 环境；Windows/PCL2 真机测试进行中；**Linux 未测**。
- **生产启动器 / 生产 jar 未做端到端**：目前是 dev `runClient/runServer` 验证。
- **Intel macOS 没有 JBR 21 资产**（问题 38）；JBR 下载 95–200 MB，需网络。
- 参数只能在启动时给：启动器不预设时**每会话最多一次自动重启**；跨会话永久生效需要启动器/整合包预设（问题 55）。
- `-PnoFocus` 在部分平台不稳（抢焦点）；L2（进世界后的 HUD/按键/截图）覆盖有限。
- CI 只跑单测 + build，不跑游戏内测试。

### 5.5 分析器

- tier 是**静态预测**，不描述 AT/JiJ/依赖；candidate 行需真实复测后才可承诺。

## 6. 回滚 / 卸载

- 热加**成功**的模组：把 jar 移出 `mods/` 后**重启**；已提交的注册表内容不能撤回，
  存档可能仍依赖它（见 5.2）。
- 热加**失败**：运行时回滚 ModList/module/mixin config/资源包/可定位的监听器；
  post-construct 之后的失败只保证“干净回滚 + 重启”，不保证可重试。
- 运行时置脏（`RunState`）后：客户端菜单/失败屏提示重启；专用服控制台按间隔重复告警，且拒绝后续 add。

## 7. 报告问题需要什么

- `logs/latest.log`（含 `capabilities:` 行与 `late access transformers:` 行）；
- `/modreloader why <jar>` 的诊断输出（只读）；
- 崩溃报告（如有）；
- 说明 JVM（是否 JBR/增强）、是否安装 MixinRuntime、模组 jar 名/版本、是否多人。
